# SPEC — 雀魂 牌譜URL → JSON エクスポータ

> 状態：**v0.1 draft（未確定あり）**。実装着手の前に §5 の調査を閉じること。
> この SPEC の §4 がサラの採点基準になる。

## 1. ゴール

雀魂の**牌譜URLを貼り付けたら、AIが読める JSON が返ってくる**。それだけ。
目的は、打った半荘をそのまま AI に読ませて検討させること。

## 2. スコープ

### やること
- 牌譜URL（1本）を入力 → 対局データの JSON を出力
- 出力をコピーできる（iPhone のクリップボードへ）

### やらないこと（暴走防止・明示）
- 牌譜の**解析・評価・何切る判定**（それは AI 側の仕事。ここは変換器）
- 統計・成績管理・履歴の蓄積・DB
- 複数牌譜の一括処理
- ネイティブ iOS アプリ化（App Store 申請）
- ログイン画面・アカウント管理UI

## 3. 使い方（想定）

1. 雀魂で牌譜URLをコピー
2. iPhone の共有シート or ブラウザで本アプリを開いて貼り付け
3. JSON が出る → コピー → AI に投げる

入口の実装形態は §5 の調査結果で決める（**Web + iOSショートカット**が第一候補）。

## 4. 受け入れ条件

### AIが閉じられる条件
- [ ] 正しい牌譜URLを渡すと、JSON が返る
- [ ] 出力 JSON が **BOMなしUTF-8・LF・parse 可能**
- [ ] 出力に最低限これが含まれる：局ごとの配牌／自摸・打牌の順序／鳴き／リーチ宣言／和了・放銃・流局と点数移動／各局の親と場風／プレイヤー4人の識別（名前は伏せ字でも可）
- [ ] 不正なURL・取得失敗・空応答で**落ちずにエラーメッセージを返す**
- [ ] 秘密情報（トークン・Cookie）がコード・リポジトリ・出力 JSON に含まれない
- [ ] 同じURLを2回渡すと同じ JSON になる（冪等）

### ren 確認が要る条件（AIは閉じられない）
- [ ] 実際の雀魂アカウントの牌譜URLで動く
- [ ] iPhone の共有シート／ショートカットから起動できる
- [ ] 出力 JSON を AI に読ませて、実際に検討ができる（＝使い物になる）

## 5. 未確定（ここを先に潰す ← ニア）

**最大の不確実性：牌譜URLを開いただけでは対局データは取れない可能性が高い。**
雀魂は Web クライアントが WebSocket 経由でレコードを取りに行く作りで、
そこにログイン済みセッションが要ると見られる。ここが閉じないと、そもそもの形が変わる。

調査で確定させたいこと：

1. **取得経路**：牌譜URLから対局データを取る現実的な方法は何か。認証は要るか。
   既存OSS（`amae-koromo` / `mjai` / MajsoulPaipuAnalyzer 系など）で流用できるものはあるか。ライセンスとメンテ状況は。
2. **出力フォーマット**：自前形式でなく既存形式に寄せる。**天鳳形式 JSON** と **mjai 形式** のどちらが、
   AI に読ませる用途で扱いやすいか（＝ツールが多く、AIも知っている）。
3. **iPhone からの入口**：共有シート → ショートカット → Web/Worker で成立するか。実例はあるか。
4. **利用規約とレート**：自動アクセスが規約上どう扱われるか。叩く頻度の安全圏。**個人利用の範囲を超えない。**

→ 結果は `apps/mahjong-paipu-export/RESEARCH.md` に落とす。

## 6. 制約

- 個人利用のみ。公開・配布はしない（公開したくなったら L3＝ren 判断）。
- 秘密情報は `.env` か Workers Secrets。コミットしない。
- 依存は最小限。動くのが先、綺麗は後。
