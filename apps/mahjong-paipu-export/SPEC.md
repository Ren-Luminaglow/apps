# SPEC — 雀魂 牌譜URL → JSON エクスポータ

> 状態：**v0.2 draft — 実装保留（L3 判断待ち）**。
> 調査（`RESEARCH.md` / 2026-07-26）で、成立には規約上のリスクを伴うことが判明した。**§7 を ren が判断するまで実装に入らない。**
> この SPEC の §4 がサラの採点基準になる。

## 1. ゴール

雀魂の**牌譜URLを貼り付けたら、AIが読める JSON が返ってくる**。それだけ。
目的は、打った半荘をそのまま AI に読ませて検討させること。

## 2. スコープ

### やること
- 牌譜URL（1本）を入力 → 対局データの JSON を出力
- 出力をコピーできる（iPhone のクリップボードへ）

### やらないこと（暴走防止・明示）
- 牌譜の**解析・評価・何切る判定**（それは AI 側の仕事。ここは変換器）
- 統計・成績管理・履歴の蓄積・DB
- 複数牌譜の一括処理
- ネイティブ iOS アプリ化（App Store 申請）
- ログイン画面・アカウント管理UI

## 3. 使い方（想定）

1. 雀魂の「シェア」から牌譜URLを長押しコピー
2. iPhone のホーム画面/ウィジェットからショートカットを起動（**クリップボードから読む**）
3. JSON が出る → クリップボードへ → AI に投げる

> **共有シート経由は想定から外した**（v0.1 からの変更）。雀魂アプリが出すのは「URLの表示＋長押しコピー」で、
> iOS の共有シートを開く導線ではないため（`RESEARCH.md` 論点3）。入口は**クリップボード**。

## 4. 受け入れ条件

### AIが閉じられる条件
- [ ] 正しい牌譜URLを渡すと、JSON が返る
- [ ] 出力 JSON が **BOMなしUTF-8・LF・parse 可能**
- [ ] 出力に最低限これが含まれる：局ごとの配牌／自摸・打牌の順序／鳴き／リーチ宣言／和了・放銃・流局と点数移動／各局の親と場風／プレイヤー4人の識別（名前は伏せ字でも可）
- [ ] 不正なURL・取得失敗・空応答で**落ちずにエラーメッセージを返す**
- [ ] 秘密情報（トークン・Cookie）がコード・リポジトリ・出力 JSON に含まれない
- [ ] 同じURLを2回渡すと同じ JSON になる（冪等）

### ren 確認が要る条件（AIは閉じられない）
- [ ] 実際の雀魂アカウントの牌譜URLで動く
- [ ] iPhone のショートカット（クリップボード入力）から起動できる
- [ ] 出力 JSON を AI に読ませて、実際に検討ができる（＝使い物になる）
- [ ] **半荘1本ぶんの JSON がクリップボード経由で AI に貼れる**（数十〜数百KB。上限で詰まらないか）

## 5. 調査結果と、残った未確定

調査完了 → **`RESEARCH.md`（2026-07-26）**。要点：

- **確定**：牌譜URLを GET しても中身は取れない。WebSocket + protobuf の `fetchGameRecord` で、
  **uid + access_token による認証が必須**。未認証で取れる経路は無かった。
- **確定**：JP サーバはログインが Yostar ID（2026-03移行）で、既存OSSのログイン実装（CN前提）が使えない。
  現実解は**ブラウザから access_token を手動で抜いて Worker に置く**方式。
- **確定**：出力形式は **mjai が AI 向けには上**（イベント名・牌表記が可読、公開スキーマあり）。
  ただし変換実装が枯れているのは tenhou.net/6 経由。
- **確定**：入口は共有シートでなく**クリップボード**（§3 に反映済み）。

### 残った未確定（実装判断の前に潰す）

1. **【最短・最重要】`mjai.ekyu.moe` が雀魂URLを直接受けて tenhou/6 JSON を落とせるか。**
   Yes なら token も規約リスクも自前で背負わず、**作るのは iOSショートカット1本**で済む。
   → クラウドからは egress ブロックで確認できなかった。**ren がブラウザで開けば30秒。**
2. **access_token の有効期限**。永続しないと見るべきだが、明示ソースなし＝未検証。
   切れる頻度次第で「コピペするだけ」の体験が成立しなくなる。
3. 出力サイズがクリップボードに載るか（§4 の ren 確認項目）。

## 6. 制約

- 個人利用のみ。公開・配布はしない（公開したくなったら L3＝ren 判断）。
- 秘密情報は `.env` か Workers Secrets。コミットしない。
- 依存は最小限。動くのが先、綺麗は後。
- **バルク収集は絶対にしない。** 1リクエスト＝1牌譜、手動トリガのみ、同一UUIDはキャッシュして再取得しない。

## 7. 規約リスク（★L3 — ren の判断待ち・ここが未決だと実装に入らない）

雀魂 利用規約 第11条の禁止事項に、以下が含まれる（ミラー経由で確認。**公式ページは取得できず＝確信度中**）：

> 逆アセンブル、逆コンパイル、リバースエンジニアリングする行為
> 当社が本サービスを通じて提供する各種コンテンツを**不正な方法で取得する行為**、又はこれを助長する行為

**「抜き出した access_token で非公式 protobuf API を叩いて牌譜を取得する」は、この両方に素直に当てはまる読みができる。**
個人利用・非公開であることは規約上の免罪符にならない（規約は用途で切っていない）。

一方で：
- 公式の摘発告知は一貫して「**対局の公平性を損なう**」＝リアルタイム支援ツールと BOT に向いている。事後の牌譜変換はそこには当たらない。
- NAGA / Mortal / 牌譜屋 / 各種ブラウザ拡張が長年公然と運営され、摘発された形跡は見つからなかった（＝**黙認**と推測。「見つからない」は「安全」の証明ではない）。

**リスクの所在：BAN されるのは ren のアカウント。** AI が引き受けられる判断ではない。
