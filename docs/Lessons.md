## L-001 | 2026-07-26 | 「たぶん動く」で閉じない（実機境界）

**何が起きた**：Emma 側の PrintingReport（T-0030）で、実装と静的QAは通ったのに、
Excel 実機での取り込み往復が AI 環境では実行不能で、完了扱いにできず止まった。
さらに UTF-8 で書いた `.bas` が日本語 Excel の VBE では cp932 読みされ、実機で文字化けした。

**なぜ**：AI が確認できる範囲（コード・静的検査）と、実機でしか確認できない範囲の境界を、
着手時点で切っていなかった。

**次からどうする**：
- 案件の SPEC に「AIが閉じられる受け入れ条件」と「ren 確認が要る条件」を**最初から分けて書く**。
- 実機境界に当たったら、手順書を書いて止める。完了報告に「やった確認／やれてない確認」を必ず併記する。

## L-002 | 2026-07-26 | サブエージェントは起動時に先読みしない

**何が起きた**：Emma 側の実証（T-0052）で、サブエージェントはローダーの指示を受け取っても、
**起動した瞬間には Read しない**（実際の読み込みは着手時まで遅れる）ことが確認された。

**なぜ**：原理的な挙動。「ローダーに書いてあるから読んでいるはず」は成立しない。

**次からどうする**：文脈担保は**発注文が持つ**。振るときに必ず `📖 reads:` を前置きする。
`📖 reads:` 無しの発注は禁止（`CLAUDE.md` §2）。

## L-003 | 2026-07-26 | ローダーの `tools:` と指示内容が食い違うと、成果物が宙に浮く

**何が起きた**：ニアに「結果を `RESEARCH.md` に落として」と発注したが、
`.claude/agents/nia.md` の `tools:` に `Write` が無かった。
ニアは調査を完走したのに**ファイルを作れず、全文を応答本文に貼って返してきた**（親が手で書き起こす羽目になった）。

**なぜ**：ローダー本文（「RESEARCH.md に落として良い」）と frontmatter の `tools:` を別々に書いて、突き合わせていなかった。
Emma 側のニアは調査専任で `Write` を持たない設計だったが、apps 版では成果物をファイルで残す運用にしたのに、
`tools:` だけ元のままコピーしていた。

**次からどうする**：
- **役に「ファイルを書け」と言うなら、`tools:` に `Write` があるか先に確認する。** 本文と frontmatter は必ずセットで見る。
- 発注前のチェック：`📖 reads:` は付けたか／**成果物の置き場を指示したなら、その役は書けるか**。
- ニアには `Write` を付与済み（2026-07-26）。ただし**上書きはしない**（新規作成のみ）と本文に明記した。

**【2026-07-27 追記】付与しても効かなかった。**
`tools:` に `Write` を足した後で再度ニアに振ったが、**またファイルを書けなかった**（「Write が無効化されていた」と報告）。
調べた範囲：ユーザーレベルの `~/.claude/agents/` は存在せず、セッション開始時に一覧された役は
Emma リポ側の `.claude/agents/`（meru・rin など apps に無い役が並んでいた）。
→ **`apps/.claude/agents/` がこのセッションのエージェント登録に効いていない**と見られる（原因は未確定）。
考えられるのは (a) セッションのプロジェクトディレクトリが `/home/user` で apps 配下が読まれていない、
(b) 役の一覧はセッション開始時に確定し、途中で足したファイルは反映されない、のどちらか（または両方）。

**当面の運用**：
- **apps リポで作業するときは、apps ディレクトリを起点にセッションを立てる**（そうすれば `apps/.claude/agents/` が効くはず・要検証）。
- それができない状況では、**サブエージェントに「ファイルに書け」と指示しない。** 応答本文で返させて、**親（エマ）がファイル化する**。
  発注文にも「成果物は応答本文で返して」と明記する。
- ローダーの `tools:` を直したら、**次の発注で本当に効いたかを確認する**（直した＝効いた、と思い込まない）。

## L-004 | 2026-07-26 | クラウドからは公式サイトが読めないことがある（egress 403）

**何が起きた**：雀魂の調査で、**公式サイト・利用規約ページ・note.com・GitHub API が軒並み 403** で取得できず、
規約の確認がミラーサイトと検索スニペット頼みになった（確信度：中止まり）。
親セッションが同じURLを再試行しても同じく 403。

**なぜ**：このリモート実行環境の egress ポリシー。Claude Code の許可設定とは**別の層**で塞がれている。

**次からどうする**：
- **規約・ライセンス・公式仕様のような「一次情報でないと意味がない」調査は、クラウドだけで閉じない前提で組む。**
- 発注文に「取得できなかったURLは推測で埋めず一覧で報告して」を必ず入れる（今回は入れていたので切り分けができた）。
- 取れなかった一次情報は、**ren がブラウザで見る**タスクとして切り出して渡す（＝実機境界と同じ扱い）。

## L-005 | 2026-07-27 | README を信じてコードを読まないと、真逆の結論を出す

**何が起きた**：雀魂の三麻対応を調べた際、初回の調査で「変換系OSSは三麻ほぼ全滅」と結論した。
根拠は各リポの README（`tensoul` の "only works with standard games with common rules"、
他リポの「4人麻雀のみ」）。**この結論は誤りだった。**
実際には `tensoul/convert.js` に三麻分岐が最初から実装されていた
（`if (3 == nplayers)` / `case "RecordBaBei"` → `"f44"` / `TSUMOLOSSOFF`）。README には一言も書かれていない。

**なぜ**：README は実装より古く、雑。書き手が「対応した」と書き足さないまま機能が入ることがある。
それを一次情報として扱ってしまった。**コードを1回 fetch すれば分かったこと。**

**次からどうする**：
- **「対応していない」という結論は、README ではなく実装で確かめる。** 不在の証明は特に慎重に。
- 逆に「対応している」と書いてあっても動くとは限らない（`MahjongCopilot` #92「三麻不起作用」が実例）。
  **README も issue も当てにならない。効くのはソースと実行結果だけ。**
- 調査の発注文に「**定義ファイル・実コードを実際に開いて、その記述で答えて**」と書く（今回はそう書いたので覆せた）。

## L-006 | 2026-07-27 | 他人のコードを参考にする前にライセンスを見る

**何が起きた**：三麻の変換で最も参考になる実装（`latorc/MahjongCopilot` の `game_state.py`・732行、
雀魂 liqi → mjai を三麻込みで直接変換）が **GPLv3** だった。

**なぜ**：麻雀ツール界隈は GPL 系と MIT/Apache 系が混在していて、見た目では区別がつかない。

**次からどうする**：
- **参考にする前にライセンスを確認する。** GPL のコードを読んで書くと、自作物も GPL の義務を負いうる。
- 個人利用・非公開なら義務は発生しないが、**混ぜたことを忘れると後で公開したくなった時に詰む。**
- 実装前に「読んでいいリポ／読まないリポ」を SPEC に明記しておく（本件は `SPEC.md` §5.5 に記載）。
